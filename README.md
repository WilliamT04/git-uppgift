Fråga 1: Versionshantering vs vanliga filer:
För Godkänt: Versionshantering är ett system som ständigt spårar och dokumenterar ändringar i koden över tid. Skillnaden mot om man bara sparar i editorn är att editorn bara skriver över den befintliga filen så att min historik försvinner. I Git skapas istället en tidslinje av sparade tillstånd. Det gör så att man kan granska och jämföra sin nuvarande version mot äldre versioner. 
För väl godkänt: Att Git sparar en tidslinje av frysta commits innebär att varje commit är ett oföränderligt tillstånd av projektets alla filer vid en specifik tidpunkt. Du kan klicka på din allra första commit på GitHub och se alla tre TODOS kvar vilket bevisar detta eftersom GitHub visar hur projektet exakt såg ut i det specifika ögonblicket. Man skriver alltså inte över koden utan nya commits läggs bara till som nya tidpunkter på tidslinjen. 

Fråga 2: Arbetsytan, Staging och Commits:
För Godkänt: Git status används för att se projekters nuvarande tillstånd, som vilka filer som ändrats eller förberetts. Git add används för att flytta valda ändringar från arbetsytan till staging area för att förbereda dem inför att spara. Git commit kör man när man vill försegla sina ändringar i staging area till ett permanent ögonblick med ett beskrivande meddelande av sina ändringar.
För väl godkänt: Relationen innebär att arbetsytan är där man skriver sin kod, staging är där man väljer ut vilka filer som ska ingå i nästa sparning och commit är där man förseglar sina ändringar och skriver ett passande meddelande innan man pushar. Om du ändrar i en fil men inte kör git add så ligger ändringen bara i arbetsytan och staging area är tomt. Då skriver git ut "no changes added to commit" eftersom git commit bara paketerar det som redan placerats i staging. 

Fråga 3: Lådan hemma vs Montern på GitHub:
För Godkänt: Mappen på min dator är där jag arbetar och gör tester lokalt. Repot på GitHub är ett repository i molnet som fungerar som en säkerhetskopia där jag även kan dela min kod med andra. Kommandot git push skickar över mina lokala commits från datorn upp till molnet (mitt repository på GitHub).
För väl godkänt: Konceptet med dem två rummen betyder att lådan hemma är min privata arbetsmiljö där jag kan committa ändringar lokalt utan att omvärlden ser det. Glasmontern på GitHub är den publika ytan som min kod och ändringar visas upp på. Andledningen till att git push svarar "Everything up-to-date" om jag inte stagat och committat är att git push bara överför färdiga commits. Om jag inte commitat något nytt så finns det ingenting för Git att ladda upp till GitHub.
